# Инструкция для ИИ-агента: развернуть голосового консультанта с телефонией

Ты — агент, который настраивает это решение для пользователя: опрашиваешь его, заполняешь
`.env`, разворачиваешь два сервера, проверяешь и объясняешь, что получилось. Работай по шагам,
ничего не пропускай и не выдумывай значений — всё, чего нет, спрашивай.

## Что получится

Голосовой консультант на OpenAI `gpt-live-1` (слушает и говорит одновременно, факты берёт
у бэкенд-модели), который:
- разговаривает с посетителем сайта в браузере (WebRTC);
- сам звонит клиентам по телефону через SIP-АТС пользователя, говорит по имени, ведёт сценарий;
- показывает оператору транскрипт и звук в реальном времени, пишет логи и записи.

Два сервера, потому что два блока: OpenAI не отвечает российским адресам, а российские АТС
не пускают иностранные. Поэтому:
- **сервер модели** — вне контура РФ (любой VPS 1 vCPU / 1 ГБ): здесь `server.mjs`, здесь ключ OpenAI;
- **сервер телефонии** — внутри РФ (VPS 2 vCPU / 2 ГБ, Ubuntu 22.04/24.04, публичный IP):
  здесь Asterisk и диалер, он регистрируется в АТС внутренним номером и звонит через неё.

Между ними — один WebSocket (`wss://<домен телефонии>/pbx/bridge`), токен + белый список IP.

## Принципы

1. Секреты — только в `.env` на машине пользователя и на серверах. Никогда не проси прислать
   пароль или ключ в чат: попроси вписать в `.env` и скажи, в какую строку.
2. Настройки АТС не меняй через API и не проси менять лишнее: нужен один новый внутренний номер
   и разрешение ему звонить наружу. Всё остальное — на своих серверах.
3. Реальные звонки заблокированы (`ALLOWED_NUMBERS=none`), пока пользователь не назовёт номер
   для теста. Первый звонок — на его собственный телефон.
4. После каждого шага показывай пользователю, что проверил и что увидел. Не заявляй «готово»
   без проверки.
5. Если что-то не сходится — смотри «Что может пойти не так» в конце, там собраны реальные грабли.

## Шаг 1. Опроси пользователя

Спрашивай по одному вопросу за раз. Что нужно и в какой строке `.env` это живёт:

| Вопрос | Что ждёшь | Строка `.env` |
|---|---|---|
| Ключ OpenAI с доступом к `gpt-live-1` | впишет сам | `OPENAI_API_KEY` |
| SSH-доступ к серверу модели вне РФ (root или sudo) | `user@host` или alias из `~/.ssh/config` | `MODEL_SSH` |
| SSH-доступ к серверу телефонии в РФ | то же | `PBX_SSH` |
| Домен для сервера телефонии с A-записью на его IP | например `pbx.example.com` | `BRIDGE_DOMAIN` |
| Почта для сертификата Let's Encrypt | адрес | `ADMIN_EMAIL` |
| Адрес АТС, на котором регистрируются внутренние номера | например `xxxxx.onpbx.ru` | `PBX_DOMAIN` |
| Отдельный внутренний номер под робота и его SIP-пароль | номер, пароль впишет сам | `PBX_EXTENSION`, `PBX_SIP_PASSWORD` |
| С какого номера звонить клиентам | номер, подключённый к АТС | `PBX_CALLER_ID` |
| Разрешены ли этому добавочному исходящие на внешние номера в АТС | да/нет — если нет, пусть включит | — |
| Формат набора для этой АТС | по умолчанию `7` + 10 цифр (onlinePBX); другие АТС могут ждать `8` или `+7` | `DIAL_PREFIX` |
| Свой номер для первого тестового звонка | 11 цифр | `ALLOWED_NUMBERS` (позже) |
| Кто консультант: имя, компания, продукт, событие | текст для профиля | `profiles/*.md` |
| Нужна ли запись реальных звонков | да/нет; напомни про уведомление собеседника | `RECORD_CALLS` |

Проверь у пользователя, что:
- внутренний номер заведён **отдельно** (не номер живого сотрудника: история и регистрации перепутаются);
- на сервере телефонии не крутится другой Asterisk с чужими настройками — если есть, скажи,
  что конфиги `/etc/asterisk` будут заменены (копия останется в `/etc/asterisk.bak-orig`);
- у обоих серверов открыт SSH и есть интернет.

Сгенерируй `BRIDGE_TOKEN`: `openssl rand -hex 24` — впиши в `.env` сам.

## Шаг 2. Локальная подготовка

```bash
cp .env.example .env      # затем заполнить по таблице выше
npm install
npm run check             # открывает настоящую Live-сессию: проверка ключа и доступа к gpt-live-1
```

`npm run check` должен напечатать `session.started` и `session.closed`. Если 401/403 —
ключ или у проекта нет доступа к `gpt-live-1`.

## Шаг 3. Сервер модели (вне РФ)

```bash
bash model-server/deploy.sh
```

Скрипт ставит Node 22, копирует проект в `/srv/gpt-voice`, заводит сервис `gpt-voice-web`,
печатает публичный IP сервера — **впиши его в `BRIDGE_ALLOW` в `.env`** (можно несколько адресов
через запятую, IPv6 — префиксом `/64`). Интерфейс оператора наружу не публикуется; доступ:

```bash
ssh -L 3000:127.0.0.1:3000 <MODEL_SSH>   # затем http://localhost:3000
```

Если пользователь хочет интерфейс по домену — nginx с basic auth перед `127.0.0.1:3000`
(WebSocket на `/api/calls/*/audio`, SSE на `/api/calls/*/events`), но по умолчанию туннель.

Для тестов сервером модели может быть ноутбук пользователя вне РФ: тогда `npm start` локально,
а в `BRIDGE_ALLOW` — его внешний адрес (`curl -4 ifconfig.me`). При смене сети адрес меняется,
мост ответит 403 — обновить `.env` и снова `bash pbx-server/deploy.sh`.

## Шаг 4. Сервер телефонии (в РФ)

```bash
bash pbx-server/deploy.sh
```

Скрипт: ставит Asterisk, nginx, certbot; заводит пользователя `gptvoice`, venv, сервис
`gpt-voice-dialer`; собирает конфиги Asterisk из `.env`; настраивает ufw (SSH, 80, 443,
SIP и RTP только с адреса АТС); выпускает сертификат для `BRIDGE_DOMAIN`; запускает всё и
показывает статус. Ждёшь в выводе:

- `── регистрация в АТС:` … **`Registered`** — Asterisk вошёл в АТС внутренним номером;
- `chan_rtp running: 1`; `── диалер:` `active` и строка `диалер слушает 127.0.0.1:8130`.

Если `Rejected`/`Unregistered` — неверный пароль или добавочный, либо АТС не пускает
регистрацию с этого IP (спросить у поддержки АТС).

Проверь доступ к мосту с сервера модели (или ноутбука): без токена должен быть `401`,
с чужого адреса — `403`:

```bash
curl -s -o /dev/null -w "%{http_code}\n" https://<BRIDGE_DOMAIN>/pbx/health            # 401 с разрешённого IP
curl -s -H "Authorization: Bearer <BRIDGE_TOKEN>" https://<BRIDGE_DOMAIN>/pbx/health     # JSON: asterisk, brain, calls
```

Перезапусти сервер модели (`systemctl restart gpt-voice-web` или `npm start`) и убедись,
что в `logs/brain.log` есть `мост: подключён`, а `GET /api/pbx/status` даёт `"connected":true`.

### Шаг 4а. Что именно делает скрипт — и как поставить руками

Если `deploy.sh` по какой-то причине не подходит (другой дистрибутив, свои правила), вот
что он делает на сервере телефонии; повторите вручную в этом порядке (Ubuntu 22.04/24.04):

1. **Пакеты:** `apt-get install -y asterisk python3-venv nginx certbot python3-certbot-nginx ufw dnsutils curl`.
   Asterisk нужен 18 и новее (в репозитории Ubuntu — 18/20): ARI, PJSIP и `chan_rtp`
   (externalMedia) входят в стандартную сборку.
2. **Конфиги Asterisk** — шаблоны в `pbx-server/asterisk/`, подставить `@@ПЕРЕМЕННЫЕ@@`
   значениями из `.env` и положить в `/etc/asterisk/` (владелец `asterisk:asterisk`, права 640):
   `pjsip.conf` (транспорт, регистрация добавочным, endpoint без гостевого доступа),
   `extensions.conf` (входящие отбиваются; `[gpt-test]` для самопроверки), `ari.conf`
   (пользователь ARI), `http.conf` (`127.0.0.1:8088`), `manager.conf` (AMI выключен),
   `rtp.conf` (10000–10200), `logger.conf`, `cdr.conf`. Старый `/etc/asterisk` сохраните копией.
   Затем `systemctl enable --now asterisk`, `asterisk -rx "core reload"`, проверка:
   `asterisk -rx "pjsip show registrations"` → `Registered`.
3. **Диалер:** пользователь `useradd -r -s /usr/sbin/nologin gptvoice`; каталог
   `/srv/gpt-voice-dialer` с `dialer.py`, `requirements.txt`, `sounds/`; окружение
   `python3 -m venv .venv && .venv/bin/pip install -r requirements.txt`; переменные в
   `/etc/gpt-voice/dialer.env` (root:gptvoice, 640): `ARI_USER`, `ARI_PASSWORD`, `BRIDGE_TOKEN`,
   `CALLER_ID`, `ALLOWED_NUMBERS`, `MAX_CALLS`, `DIAL_PREFIX`, `RECORD_CALLS`; сервис —
   `pbx-server/gpt-voice-dialer.service` в `/etc/systemd/system/`, `systemctl enable --now gpt-voice-dialer`.
   Каталоги: `/var/spool/asterisk/recording` (asterisk), `/var/log/gpt-voice` (gptvoice).
4. **nginx + TLS:** vhost из `pbx-server/nginx-pbx.conf` с вашим доменом и `allow`-строками
   для адресов сервера модели → `/etc/nginx/sites-available/gpt-voice-pbx`, симлинк в
   `sites-enabled`; сертификат `certbot certonly --nginx -d <домен>`; `nginx -t && systemctl reload nginx`.
5. **Файрвол (ufw):** `allow OpenSSH`, `allow 80/tcp`, `allow 443/tcp`,
   `allow from <IP АТС> to any port 5060 proto udp`, `allow from <IP АТС> to any port 10000:10200 proto udp`,
   `ufw enable`. Никаких правил «5060 отовсюду».
6. **Проверка:** `curl https://<домен>/pbx/health` без токена → 401; с чужого адреса → 403;
   `journalctl -u gpt-voice-dialer -n 5` → `диалер слушает 127.0.0.1:8130` и `ARI: слушаем события`.

## Шаг 5. Профиль консультанта

Профиль — файл в `profiles/`, читается на каждый запрос, перезапуск не нужен. Возьми шаблон:
`profiles/example-call.md` для звонков, `profiles/example-course.md` для сайта. Заполни все
`[КВАДРАТНЫЕ СКОБКИ]` из того, что сказал пользователь, и удали лишнее. Правила, которые
нельзя убирать: женское/мужское лицо всегда одно; «Вы»; факты только из «Что знает»; раздел
«Чего в базе нет — не выдумывай» обязателен; в «Что знаешь сама» — то, что нужно отвечать
мгновенно (время, место, ссылка).

Проверь профиль текстом до всякого голоса — прогони «Как думает» + «Что знает» через бэкенд-модель
на типичных репликах клиента (что это, во сколько, не смогу, где ссылка, это платно, уход от темы,
«ты бот?»). Пример:

```js
import OpenAI from "openai";
import { loadProfiles, sessionFor } from "./lib/profiles.mjs";
const p = (await loadProfiles()).get("example-call");
const s = sessionFor(p, { backendModel: "gpt-5.6-terra", phone: true });
const r = await new OpenAI().responses.create({ model: "gpt-5.6-terra",
  instructions: s.delegation.responses.instructions, input: "Клиент говорит: «А во сколько это?»" });
console.log(r.output_text);
```

Ответы должны быть короткими, от нужного лица, без выдуманных фактов.

## Шаг 6. Самопроверка без телефона

В интерфейсе (или `POST /api/calls {"to":"test:sim1","profile":"<id>","name":"Тест"}`) позвони на
`test:sim1`: Asterisk сыграет абонента заготовленными репликами (`pbx-server/sounds/`), разговор
пройдёт по всему тракту — RTP → мост → Live → обратно. Проверь:

- в интерфейсе появляются реплики обеих сторон, «Фоновая работа» показывает делегирование;
- `logs/calls/<id>.txt` — расшифровка; `logs/calls.jsonl` — сводка с `talk_seconds > 0`;
- на сервере телефонии `/var/log/gpt-voice/dialer.log` — строки `звук — из АТС N кадров, в АТС M`
  с растущими счётчиками; запись в `/var/spool/asterisk/recording/gpt-test-*.wav`.

Свои сценарии: добавь `sim2` в `[gpt-test]` в `pbx-server/asterisk/extensions.conf` и файлы
`pbx-server/sounds/sim2-*.wav` (8 кГц, моно, 16 бит).

## Шаг 7. Первый настоящий звонок

1. `ALLOWED_NUMBERS=<номер пользователя>` в `.env`, `bash pbx-server/deploy.sh`.
2. В интерфейсе, вкладка «Телефония»: промпт (или «Основа» из профиля), файлы-инструкции,
   в поле «Кому звонить» — `номер имя` (по одному на строку или через запятую), «Позвонить по очереди».
   Пользователь отвечает и разговаривает; следующий номер набирается автоматически через 3 с.
3. После звонка разбери логи вместе с ним: `npm run calls`, расшифровку, `dialer.log`
   (`ответили через N с`, счётчики звука), при `RECORD_CALLS=on` — запись.
4. Послушай запись или прочитай расшифровку записи: типичные правки после первого звонка —
   произношение названий (добавь в «Произношение») и слишком долгие «сейчас уточню» (перенеси
   факт в «Что знаешь сама»).

Только после этого расширяй `ALLOWED_NUMBERS` (пусто = любые номера).

## Шаг 8. Что рассказать пользователю в конце

- Где интерфейс и как в него попасть; как звонить; что показывает полоса дуплекса.
- Где логи и записи (см. `docs/logs.md`), как посмотреть сводку (`npm run calls`).
- Как менять поведение консультанта — файлы в `profiles/`, без перезапуска.
- Как остановить: `ssh <PBX_SSH> systemctl disable --now asterisk gpt-voice-dialer`; как поднять
  снова: `bash pbx-server/deploy.sh`.
- Что стоит: голос $0.05/мин посекундно + бэкенд + минуты АТС.
- Юридическое: маркировка деловых звонков и согласие абонента на автоматические вызовы (РФ);
  запись разговора требует уведомления собеседника.

## Что может пойти не так — проверено на практике

| Симптом | Причина | Что делать |
|---|---|---|
| `Registered` есть, но звонок обрывается через полсекунды, в SIP-трассе `404 Not Found` после `183` | АТС не поняла формат номера (onlinePBX отвечает 404 на `8…`) или добавочному запрещены исходящие | `DIAL_PREFIX=7` (или тот, что ждёт АТС); в АТС включить исходящие для добавочного через нужный номер |
| Endpoint `Unavailable`, звонки не идут | в `pjsip.conf` был `qualify_frequency`, АТС не отвечает на OPTIONS | в шаблоне qualify нет; не добавляйте |
| ARI `POST bridges/…/record → 500` | нет каталога `/var/spool/asterisk/recording` | deploy.sh создаёт его; проверьте права `asterisk:asterisk` |
| Мост отвечает `403` серверу модели | адрес сервера модели не в `BRIDGE_ALLOW`; частая причина — домен без AAAA, а в списке только IPv6 | впишите IPv4 (`curl -4 ifconfig.me`) и IPv6 `/64`, `bash pbx-server/deploy.sh` |
| `мост: отключён {"code":1006}` сразу после деплоя | диалер перезапустился | норма, мозг переподключится за 2–8 с |
| Звонок «завершён» мгновенно, в `brain.log` `мост: отключён {"code":1002}` на старте | мост закрыл сокет с protocol error | смотреть `reason` в `brain.log` и `мост: ошибка сокета` в `dialer.log`, повторить звонок |
| Ответили, но слышно только одну сторону | RTP от АТС не доходит (файрвол) или обратно | `dialer.log`: если `frames_in` не растёт — открыть RTP с адреса АТС; если `speech_out` не растёт — проблема мозг↔мост |
| Пустая запись самопроверки (44 байта) | запись через MixMonitor на Local-канале | используется ARI-запись моста, как в `dialer.py` |
| `session.started` нет, `error 401/403` | ключ OpenAI или нет доступа к `gpt-live-1` | `npm run check` |
| Кнопка «Позвонить» неактивна | мозг ещё не подключился к мосту | статус обновляется сам каждые 4 с; иначе `logs/brain.log` |
| Микрофон в браузере не запрашивается | страница не на `localhost`/HTTPS | туннель `ssh -L` или HTTPS |
| Робот говорит названия с ошибками | TTS не знает ударений | раздел «Произношение» в профиле |

## Безопасность — что должно быть на выходе

- SIP (5060/udp) и RTP (10000–10200/udp) открыты только для адреса АТС; никаких широких правил.
- В Asterisk нет анонимных endpoint'ов, входящие отбиваются, набрать наружу может только ARI с localhost;
  ARI на `127.0.0.1:8088` под паролем, AMI выключен.
- Мост `/pbx/`: белый список адресов + токен. Проверено `403`/`401`.
- `ALLOWED_NUMBERS` — не пустой, пока идут тесты. Ключи и пароли — только в `.env` (chmod 600).
- Интерфейс оператора не торчит в интернет без аутентификации.
