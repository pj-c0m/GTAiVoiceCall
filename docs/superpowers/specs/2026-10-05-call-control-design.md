# GUI управления звонками и устойчивое планирование

Дата: 2026-10-05. База: `043ce4364b9de6df5ae77187530698843fce3bba`.
Статус: спецификация для review владельцем; реализация ещё не начата.

## Цель и границы

Оператор выбирает адресата, время и содержание разговора, проверяет карточку
и запускает либо планирует один звонок. Запланированный звонок выполняется
сервером при закрытом браузере. Сохраняются два сервера, Asterisk/PJSIP/ARI,
externalMedia, PCMA 8 kHz, WebSocket bridge, Live API и MIT attribution upstream.
Браузерные режимы разговора и промпта остаются доступны.

Разрешены локальная реализация, offline/mock проверки, визуальный smoke,
commit/push task-ветки и handoff. Интеграция main, production deployment,
платный API smoke и реальные PSTN-звонки не входят в этот цикл.
Allowlist не открывается; `record=off`, один канал. Секреты main не копируются.

## Выбранный подход

Локальный scheduler внутри единственного процесса model server с SQLite
на постоянном диске. Использовать Node 22 `node:sqlite`, без внешнего queue
service; проверять доступность runtime перед запуском. Транзакции, WAL и
`synchronous=FULL` сохраняют задания до побочного эффекта. Второй dispatcher
для того же хранилища запрещён эксклюзивным process lock; устаревший lock
снимается только после подтверждения отсутствия владельца. Неизвестное
состояние lock останавливает dispatcher. Файл БД и каталог закрыты для
посторонних, исключены из Git. Повреждение БД или ошибка записи запрещает
новые звонки и возвращает понятную ошибку, без сброса состояния.

Альтернативы: браузерный таймер не переживает закрытие страницы; внешняя
очередь требует дополнительного сервиса и не устраняет неизвестный исход
PBX-команды. SQLite достаточно для одного оператора и одного канала.

## Операторский поток

Основной экран телефонии: форма «Новый звонок», список запланированных и
история. Светлая поверхность, графитовый текст и существующий лаймовый
акцент. Настройки сгруппированы по смыслу; редкие параметры раскрываются.

1. Контакт из сохраняемого на сервере списка или ручной номер и имя.
   Контакты содержат только имя и номер; доступны добавление и удаление.
2. «Сейчас» или дата/время. Видимый IANA timezone по умолчанию
   `Europe/Moscow`, его можно изменить. Карточка показывает локальное время,
   timezone и UTC offset. Дата в прошлом отклоняется.
3. Тема и цель, дополнительные инструкции, сценарий из существующих
   профилей или собственный промпт, голос из серверного списка.
   Файлы обрабатываются существующим `/api/files`; сохраняется извлечённый
   текст и имя, исходный binary не хранится. Перед созданием видны файлы,
   размеры текста и ошибки извлечения.
4. Максимальная длительность: 30–1800 секунд, default 300; отсчёт от ответа.
5. Отдельная карточка проверки: адресат, время, тема, цель, профиль, голос,
   файлы, инструкции и лимит. После подтверждения кнопка блокируется до
   ответа; повтор HTTP использует тот же idempotency key.

Редактирование формы не меняет уже сохранённое задание. Для изменения
времени/содержания оператор отменяет старое и создаёт новое. Автоповтора,
повторяющихся расписаний и пакетного планирования в этой версии нет.

На mobile форма и списки идут одной колонкой; карточка проверки доступна
без горизонтального scroll. Подписи полей, keyboard navigation, focus,
ошибки рядом с полями и объявления статуса обязательны. Перезагрузка
страницы восстанавливает список с сервера, не запускает задания повторно.
Закрытие страницы не посылает hangup для серверного задания.

## Данные и API

Отдельные модули: хранилище, валидация/timezone, scheduler и UI телефонии.
`server.mjs` связывает их с существующими профилями и CallHub.

Задание хранит UUID, idempotency key и hash нормализованного запроса,
адресата, UTC instant, исходное wall time/timezone/offset, тему и цель,
instructions, тексты файлов, snapshot выбранного профиля и готовой session
configuration, maxDurationSeconds, createdAt, состояние, attemptId,
callId/dialerId, времена, причину и результат. Будущая правка профиля
не меняет одобренный разговор. Внутренняя session не выдаётся в list API.

`POST /api/jobs` создаёт задание «сейчас» или на будущее; одинаковый key
с тем же payload возвращает существующий результат, с другим — 409.
`GET /api/jobs` возвращает ограниченный список кратких карточек;
`GET /api/jobs/:id` — детали и сохранённый результат;
`DELETE /api/jobs/:id` — отмена только ещё не отправленного задания.
Для начавшегося звонка отдельный stop endpoint отправляет hangup,
а UI показывает «Завершаем» до результата. Контакты имеют отдельный CRUD API.
Все новые mutations проверяют Origin по существующей localhost policy;
без Origin допускаются локальные CLI. UI остаётся на loopback/SSH tunnel.
Публичная публикация потребует отдельной авторизации и аутентификации.

Сервер ограничивает длины полей и общий текст файлов, число контактов и
заданий; не принимает произвольные Live session objects от клиента.
Номер нормализуется для PSTN; `test:sim1` поддерживается для тестового пути.
Контакт не является разрешением звонить: PBX allowlist сохраняет authority.

Timezone преобразуется на сервере: несуществующие и двусмысленные wall times
при DST отклоняются с пояснением, оператор выбирает однозначное время.
UI preview и POST используют один серверный resolver; UTC instant не
пересчитывается после сохранения при изменении timezone браузера.

## Lifecycle и предотвращение повторов

Состояния: `scheduled`, `waiting`, `dispatching`, `active`, `completed`,
`failed`, `cancelled`, `missed`, `unknown`. Терминальные состояния не
переходят обратно в runnable; новый звонок требует нового задания.

Dispatcher выполняет не более одной попытки за tick. До команды PBX
транзакция сохраняет `dispatching` и attemptId. После этой границы никакой
exception, timeout, disconnect или restart не возвращает задание в очередь.
Это at-most-once attempt, а не обещание exactly-once PSTN.

При запуске процесса `dispatching`/`active` становятся `unknown` с причиной
«процесс остановился во время попытки». Их нельзя повторять автоматически.
Завершённые задания не отправляются снова. Сбой после сохранения попытки,
но до отправки может потерять звонок — предпочтительно случайному дублю.

Задание можно запускать до 120 секунд после назначенного времени.
Занятый канал/неподключённый или неизвестный PBX даёт `waiting`; по истечении
окна — `missed`. При restart уже просроченные задания становятся `missed`.
Причина видна оператору; ручное перепланирование создаёт новое задание.

`CallHub` принимает hello snapshot PBX и считает readiness подтверждённой
только после hello. Активные чужие/orphan PBX каналы блокируют dispatcher.
Проверка одного канала применяется ко всем путям start, включая старые
immediate/campaign endpoints: они не могут обойти занятость scheduler.
Disconnect сбрасывает readiness. Никакого автоматического завершения чужих
звонков; после reconnect нужен подтверждённый пустой snapshot.

Cancellation и dispatch сериализованы: если cancel committed до claim,
команда не отправляется; после claim отмена возвращает 409, UI предлагает
остановить попытку. Повтор stop не создаёт новый звонок. Максимальная
длительность enforced сервером; hangup не зависит от браузера.

`completed` требует подтверждённого PBX ended и закрытой Live-сессии;
PBX отказ/no answer дают `failed`. Потеря bridge либо отсутствие подтверждения
cleanup дают `unknown`, даже если локальные объекты удалены. Освобождение
локального CallHub slot само по себе не доказывает PBX cleanup.
Pending cleanup блокирует следующий запуск до подтверждения PBX emptiness.

## Результаты и стоимость

Сервер сохраняет transcript delta/turns и окончательную сводку в БД;
после restart история доступна независимо от in-memory finished map.
UI показывает dialing/answered/завершение, причины отказа, ring/talk duration,
transcript, Live usage и время обновления. Сохранённые промежуточные данные
не выдаются за окончательный результат после crash.

Стоимость обозначается «Оценка Live», по существующему тарифу проекта
$0.05/мин и usage seconds. Это не полный счёт: PBX и backend не включены;
при отсутствии usage показывается «Нет данных», не $0. Тариф сохраняется
с результатом, его актуальность не утверждается и платный lookup не нужен.

## Проверки и handoff

Offline тесты с fake clock и fake PBX/Live проверяют: запуск при закрытом
браузере; persistence/reopen; crash до/после claim и после отправки;
отсутствие второго вызова после unknown; double POST; конкурентные ticks;
cancel против claim; missed window; busy канал и старые endpoints;
hello с orphan; bridge disconnect; cleanup timeout; лимит длительности;
transcript/usage после restart; DST gap/fold; ошибка диска и повреждённая БД.
API integration тесты используют реальный HTTP и временное хранилище,
не подключая OpenAI или production PBX. Проверяются существующие regression
tests. Desktop/mobile визуальный smoke включает заполнение формы,
карточку проверки, создание, отмену, ошибки и восстановление списка.

CHANGELOG и DEPLOY дополняются на русском: runtime, постоянный путь БД,
единственный процесс, backup/restore, состояния после restart, локальные
команды и границы проверки. Реализация заканчивается scoped commit/push
task-ветки и handoff main с SHA, PASS и NOT VERIFIED.
Production/PSTN acceptance новой функции остаётся NOT VERIFIED.
