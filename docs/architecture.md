# Как устроено

## Два контура

| | Сервер модели (вне РФ) | Сервер телефонии (в РФ) |
|---|---|---|
| Что стоит | `server.mjs` (Express, интерфейс, WebRTC-сессии), `lib/calls.mjs` (мозг звонков) | Asterisk 18+, `pbx-server/dialer.py`, nginx с TLS |
| Что знает | ключ OpenAI, профили, логи и записи | SIP-пароль добавочного, токен моста, пароль ARI |
| Куда ходит | OpenAI (Live WebSocket, Responses), мост | АТС (SIP/RTP), ARI на localhost |
| Кто к нему ходит | оператор (SSH-туннель) | сервер модели (WSS, токен, белый список), АТС (SIP/RTP) |

## Поток звонка

1. Оператор: номер, имя, профиль → `POST /api/calls`. Мозг открывает Live-сокет и шлёт мосту
   `call.start {slot, to, record}`.
2. Диалер через ARI просит Asterisk набрать `PJSIP/<DIAL_PREFIX+10 цифр>@obpx_endpoint`.
   Asterisk зарегистрирован в АТС внутренним номером; АТС звонит с номера из своих правил.
3. Абонент ответил → Asterisk: mixing-bridge + канал `externalMedia` (RTP A-law на localhost).
   Диалер шлёт кадры по 20 мс мозгу (`[слот][A-law]`), мозг — в Live (`session.input_audio.append`,
   формат `audio/pcma 8000`), ответ модели (`session.output_audio.delta`) — обратно.
4. Live-сессия стартует в момент ответа абонента: до этого минуты не тратятся.
5. Положили трубку → `session.close` → `session.closed` с usage; мозг пишет сводку и расшифровку.

Полный дуплекс сохраняется: обе стороны говорят одновременно, модель сама останавливается,
когда её перебивают.

## Протокол моста

Одно WebSocket-соединение, мозг — клиент, переподключается сам (2 → 30 с).

| Направление | Сообщение |
|---|---|
| мозг → мост | `{"type":"call.start","slot":1,"to":"+7…","record":false}`, `call.hangup`, `call.flush`, `ping` |
| мост → мозг | `{"type":"hello","calls":[…]}`, `{"type":"call.state","slot":1,"id":"…","state":"dialing\|ringing\|answered\|ended","reason":…,"talked":…}` |
| оба | бинарные кадры: первый байт — слот, дальше A-law (160 байт = 20 мс) |

`test:<имя>` вместо номера → `Local/<имя>@gpt-test/n`: самопроверка без телефонии.

## Профили

Файл `profiles/<id>.md`: шапка (`label`, `description`, `name`, `voice`, `search`, `phone`)
и три раздела. «Как говорит» → инструкции `gpt-live-1` (манера, сценарий, удержание темы,
факты для мгновенного ответа). «Как думает» + «Что знает» → бэкенд-модели (правила честности,
база знаний). Голосовая модель ведёт разговор, бэкенд отвечает за факты — поэтому всё, что
должно звучать мгновенно, кладут в «Как говорит», а всё, за что можно соврать, — в «Что знает».

RAG не используется намеренно: база на один продукт — несколько тысяч токенов, она целиком
в промпте; ретрив добавил бы слышимую задержку. Когда база перестанет влезать — в
`lib/profiles.mjs` вместо `profile.knows` подставляется результат поиска.

## Что стоит знать про API

- `gpt-live-1` живёт только на `v1/live/sessions`; SIP у OpenAI — только входящий, поэтому
  исходящие делает своя АТС, а звук идёт по WebSocket в G.711.
- Голос и инструкции не меняются после старта сессии; текст в сессию отправить нельзя.
- Прервать агента: `session.input_audio.mute` → `session.input_audio.muted`.
- Завершение: `session.close` и ждать `session.closed` с итоговым `usage`.
